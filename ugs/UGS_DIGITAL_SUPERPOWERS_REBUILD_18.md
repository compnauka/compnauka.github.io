# 2. Продукт: що незмінне

## 2.1. Педагогічний принцип

Це не енциклопедія, не підручник з усієї інформатики й не тренажер заради зірочок. Дитина вчиться **діяти**: обрати потрібний пристрій, розпізнати інформацію, виконати цифрову роботу, перевірити повідомлення, не розкрити особисте, дати команди виконавцю.

**Одиниця досягнення = конкретна перевірена навичка.** Розділи за віком не блокуються. Зміст можна проходити в довільному порядку; складніші завдання мають локальні підказки, а не вимагати проходження «2 класу».

## 2.2. Технічні обмеження

- Статичний проєкт: **HTML, CSS, vanilla JavaScript, локальні SVG/PNG/WebP/аудіо/відео**.
- Без React, Vue, Tailwind, бібліотек UI, npm-збірки, серверної авторизації та зовнішніх CDN.
- Коректна робота на GitHub Pages та будь-якому статичному HTTP-хостингу.
- Локальний прогрес із безпечним fallback; не вимагати персональних даних дитини.
- Адаптивність від **320 px** до широких екранів, reflow при **200–400%** масштабуванні.
- Кешування статичного shell через service worker, якщо воно вже реалізоване. Не кешувати автоматично великі відеофайли.
- Інтерфейс українською; написи й аудіо повинні узгоджуватися.

## 2.3. Комунікація з дитиною

**У дитячому інтерфейсі:** «Цифрові суперсили», «Обери», «Знайди», «Розклади», «З’єднай», «Спробуй», «Готово», короткі запитання й картинки.

**Лише на сторінці для дорослих:** «цифровий мінімум», «компенсація освітніх втрат», «без реєстрації», «без оцінок і таймерів», умови офлайн, спосіб збереження прогресу, педагогічна методика, відповідність стандарту.

**Короткий текст — не відмова від навчальних понять.** Слова «команда», «модель», «код», «файл», «пароль», «перевір» допустимі, якщо є темою уроку й відразу показані на прикладі.

### 4.1. Обов'язкові секції

1. **Назва й одне запитання.** Запитання описує головну ідею, не «мету і завдання уроку».
2. **Відео або анімація з озвученням.** Цільова тривалість **90–150 секунд**, максимум **180 секунд**; одна чітка навчальна ідея. Відео не запускається автоматично. Локальний poster, українські субтитри `.vtt` і текстовий виклад для доступності. Якщо реального файлу ще немає — явно позначити в робочій документації **«відео не готове»**; тимчасовий storyboard не називати відео.
3. **«Запам'ятай».** 2–3 короткі картки з аудіо; не дублювати слово в слово 2 хв відео.
4. **«Спробуй».** Одна найпростіша дія з демонстрацією й підказкою.
5. **«Потренуйся».** 2–3 **вкладки** з різними, навчально релевантними механіками. Не використовувати ті самі вкладки всюди; філворд не є обов’язковим.
6. **«Перевір себе».** 4 нові контрольні завдання з відкладеним результатом без підказування відповіді під час проходження.

### 4.2. Опційні секції

- **«Створи сам».** Тільки якщо конкретна творча/графічна дія підтверджує навчальну ціль. Не вставляти порожній графічний редактор у кожен урок. Оцінювання відкритого малюнка не автоматизувати без об'єктивних ознак.
- **«Допомога».** Коротка демонстрація або озвучення за потреби, не великий текст.
- **«Далі».** Рекомендація наступної теми після завершення; не блокувати інші уроки.

### 4.3. Поведінка сторінки

- **Один видимий активний інтерактив** у вкладках. Вкладки переключають лише вправу, не весь урок.
- Відео й картки можуть залишатися вище; дитина може прокрутити сторінку назад. Перевірка відкривається кнопкою без прихованого примусу.
- Усі завдання мають кнопку **«Послухати»** (або звукову іконку з доступною назвою); мовлення не вмикати автоматично.
- На телефоні вкладки — прокрутний ряд або адаптивна сітка з великими зонами. Не створювати горизонтальне переповнення сторінки.
- На планшеті/desktop робоча область ширша, але речення не розтягуються на весь екран.
- Не додавати довгих дорослих пояснень на дитячу сторінку; посилання на додаткові ресурси — у `adults.html`.

# 5. Контракт вправ і підсумкових перевірок

## 5.1. Механіки (спершу повторне використання)

| Механіка | Рекомендоване використання |
|---|---|
| `choice` / `quizRounds` | Вибрати 1 із **4** карток із зображеннями/озвученням |
| `tap` / `controlLab` | Дотик, клік, кнопки, скрол, прості дії |
| `match` | Пари; обов'язкова альтернатива «тап об'єкт → тап відповідь» |
| `sort` | Групування за ознаками; кнопкова альтернатива перетягуванню |
| `sequence` | Порядок дій, символів, кроків |
| `mediaLab` | Текст/фото/звук/відео |
| `virtualKeyboard` | Реальне натискання клавіш, пробіл, Enter, Backspace |
| `saveFind` | Створення → збереження → відкриття |
| `browserSim` / `searchSim` | Локальні безпечні симуляції браузера та пошуку |
| `safetyScenarios` / `passwordGame` | Короткі ситуації онлайн-безпеки |
| `robotUI` / `commandLab` / `routeRunner` | Виконавець, команди та маршрути |
| `debugRunner` / `repeatRunner` | Пошук помилки, повтори |
| **нове** `modelMatch` | Модель ↔ реальний об'єкт ↔ схема/план |
| **нове** `pixelCode` | Розфарбовування за умовним кодом, створення коду |
| **нове** `sourceCheck` | Факт / думка / потребує перевірки; порівняння свідчень |
| **нове** `miniEditor` | Зображення + підпис + редагування та збереження |

**Умови:** якщо `choice` — **рівно чотири варіанти**; у `sort`, `sequence`, `match` кількість цілей визначається педагогічним змістом, не штучно дорівнює чотирьом. Не вимагати точного drag-and-drop як єдиного способу відповіді.

## 5.2. Перевірка після навчання

- **4 контрольні завдання** на навичку за замовчуванням, 3–5 допустимо за обґрунтуванням.
- Приклади **не тотожні** тренувальним: нові картинки, маршрут, об'єкти або ситуації.
- Для звичайного `choice` — 4 відповіді (усі правдоподібні, лише одна правильна); зображення + коротке слово + аудіо.
- Не відкривати правильну відповідь після помилки в підсумковому режимі; лише коротко підтвердити вибір і перейти далі. Після завершення можна показати, що варто повторити, без приниження.
- `Вмію` — 4/4 незалежних дій без підказок; `Майже вмію` — 3/4 або самостійне виправлення після складності; `Тренуюся` — 0–2/4. Це **правила MVP, що потребують педагогічної перевірки**, а не «доведена» шкала компетентностей.
- Для спеціальних механік (`grid`, `miniEditor`, клавіатура) контроль 4 чітко визначених умов, а не чотири випадкові кліки; оцінювати навчальну ціль, не побічну моторну точність.
- Під час практики помилки не штрафуються; оцінювання після повторних проходжень **не знижує раніше підтверджений вищий статус** без явної переоцінки за рішенням методиста.

## РОЗДІЛ A. ПРИСТРОЇ

### Урок 01. Для чого цей пристрій?

- **Запитання для дитини:** «Що допоможе це зробити?»
- **Результат:** дитина вибирає відповідний пристрій, відрізняє введення (мікрофон, клавіатура, камера), виведення (екран, колонки, принтер) на рівні дій, не заучує класифікацію.
- **Юна/Юджі:** Юджі хоче сфотографувати метелика, почути пісню й роздрукувати малюнок.

**Відео, 5 кадрів:** (1) Юджі дивиться на метелика, бере камеру та фотографує. (2) Юна слухає мелодію в навушниках: звук надходить до вух. (3) Хтось натискає клавішу — на екрані з'являється літера. (4) Малюнок з'являється на папері з принтера. (5) Юна показує кілька пристроїв: «Для кожної справи є свій помічник».

**Запам'ятай (картки для дитини):**
1. «Камера фотографує.»
2. «Навушники відтворюють звук.»
3. «Клавіатурою вводимо. На екрані бачимо.»

**Спробуй:** «Чим зробити фото?» — обрати камеру з чотирьох великих ілюстрацій (`choice`). Показати один приклад до першої дії.

**Потренуйся — 3 вкладки:**
- **«Обери» (`choice`):** для «слухати музику» вибрати навушники серед навушників, принтера, клавіатури, камери; інші три ситуації: «надрукувати на папері», «набрати слово», «показати малюнок».
- **«З'єднай» (`match`):** камера↔фото; мікрофон↔запис голосу; принтер↔паперовий малюнок; екран↔показ зображення. Тап→тап обов'язково.
- **«Знайди» (`tap`):** у візуальному робочому місці знайти клавіатуру, екран, мишу, навушники за озвученим завданням.

**Створи сам:** не потрібно.

**Перевір себе — 4 НОВІ ситуації:**
1. «Що запише твій голос?» → **мікрофон** (опції: мікрофон, монітор, миша, принтер).
2. «Що покаже мультфільм?» → **екран** (опції: екран, клавіатура, камера, мікрофон).
3. «Що надрукує малюнок на папері?» → **принтер** (опції: принтер, колонки, ноутбук, камера; не вибирати ноутбук як прямий пристрій друку).
4. «Чим можна рухати вказівник на комп'ютері?» → **миша** (опції: миша, принтер, навушники, колонки).

**Методична пастка:** не казати, що смартфон «тільки для дзвінків» або що комп'ютер — тільки системний блок. Дії й пристрої можуть мати кілька функцій: формулювати так, щоб була одна однозначна відповідь.

### Урок 02. Я керую пристроєм

- **Запитання:** «Як сказати пристрою, що робити?»
- **Результат:** натискає, вибирає, перетягує, прокручує; знає прості правила посадки, перерв і поводження з технікою.
- **Маскот:** Юна показує рух пальцем, Юджі — курсор миші.

**Відео, 5 кадрів:** (1) Палець натискає велику кнопку — відкривається зображення. (2) Курсор миші натискає ту саму кнопку. (3) Об'єкт пересувається до місця перетягуванням. (4) Сторінка прокручується вниз, щоб знайти зірку. (5) Юна сидить зручно, тримає напій осторонь і робить коротку паузу.

**Запам'ятай:**
1. «Натисни, щоб обрати.»
2. «Перетягни, щоб пересунути.»
3. «Сиди зручно. Роби перерви.»

**Спробуй:** тапнути/клікнути на зірку; демонстрація першого руху (`controlLab`).

**Потренуйся:**
- **«Натисни» (`tap`):** 4 великі кнопки-фігури; потрібно натиснути названу фігуру.
- **«Перенеси» (`drag-target` / `controlLab`):** перенести рюкзак на полицю; альтернатива обрати рюкзак → обрати полицю.
- **«Знайди внизу» (`scroll`):** у невеликій внутрішній прокрутці знайти і натиснути квітку; передбачити видимий скролбар і клавіатурну прокрутку.

**Створи сам:** опціональна вправа «Проведи лінію від Юни до зірки» (`draw-path`). Точність оцінювати лише як роботу з курсором/пальцем, із широкою доріжкою.

**Перевір себе:** (1) натиснути потрібний квадрат серед чотирьох фігур; (2) перемістити куб у коробку будь-яким доступним способом; (3) прокрутити список і знайти сонце; (4) з чотирьох **картинок поведінки** обрати безпечну посадку без напою біля техніки. Вважати успішним виконання дії, не швидкість.

**Застереження:** на пристроях без миші не вимагати подвійного кліку або hover; не вводити жорстких секундних нормативів екранного часу.

### Урок 03. Я пишу на клавіатурі

- **Запитання:** «Як написати слово?»
- **Результат:** використовує букви, цифри, Пробіл, Backspace, Enter; виправляє короткий набір символів.

**Відео, 5 кадрів:** (1) На екрані слово «КІТ» — його можна набрати буква за буквою. (2) Два слова розділяє Пробіл: «МІЙ КІТ». (3) Зайву літеру прибираємо Backspace. (4) Enter переносить курсор на новий рядок у редакторі (не обіцяти однакової поведінки в усіх застосунках). (5) Юджі показує результат.

**Запам'ятай:**
1. «Клавіші пишуть букви й цифри.»
2. «Пробіл розділяє слова.»
3. «Backspace стирає. Enter — новий рядок тут.»

**Спробуй:** натиснути підсвічену літеру на локальній клавіатурі, побачити її в полі (`virtualKeyboard`).

**Потренуйся:**
- **«Склади» (`virtualKeyboard`):** набрати за зразком «ДІМ», «КІТ», «ЛІС» — реальними натисканнями, не перетягуванням літер.
- **«Пробіл» (`virtualKeyboard`):** зробити зі «МІЙКІТ» → «МІЙ КІТ»; коротке поле, помітний курсор.
- **«Виправ» (`virtualKeyboard`):** прибрати зайву «А» зі «СОАНЦЕ» за обмеженим прикладом, де операція однозначна; вставити знак/новий рядок у безпечній моделі редактора.

**Створи сам:** короткий підпис під вибраною картинкою (1–2 слова). На телефоні можна користуватися локальною навчальною клавіатурою, реальна системна клавіатура — опційно, за свідомою дією. Уміст має лишатися видимим при відкритті клавіатури.

**Перевір себе:** (1) набрати «ЛІС»; (2) набрати «Я ТУТ» із пробілом; (3) виправити одну помилку через Backspace; (4) в моделі редактора зробити новий рядок і ввести цифру «2». Чотири окремі дії, перевірка операцій, а не орфографічної грамотності.

**Не підміняти:** завдання зі складання слова з перетягуваних літер **не** підтверджує вміння вводити текст.

### Урок 04. Я розрізняю інформацію

- **Запитання:** «Як ми отримуємо інформацію?»
- **Результат:** упізнає текст, зображення, звук, відео; розуміє, що бачимо очима, чуємо вухами, можемо відчувати дотик і запах у реальному світі.

**Відео, 5 кадрів:** (1) Юна бачить веселку (очі). (2) Юджі чує дзвоник (вуха). (3) На екрані з’являються **текст**, **фото**, **звук** (кнопка ▶), **відео** (видимий рух). (4) Дитина торкається холодного предмета; запах квітки — **реальний світ**, не «запах з екрана». (5) Юна порівнює чотири види цифрової інформації.

**Запам'ятай:**
1. «Очима бачимо. Вухами чуємо.»
2. «Текст читаємо. Зображення розглядаємо.»
3. «Звук слухаємо. На відео є рух.»

**Спробуй:** показати малюнок яблука, обрати тип «зображення» з чотирьох великих карток (`mediaLab`).

**Потренуйся:**
- **«Розклади» (`sort`):** «Текст / Зображення / Звук / Відео»; об'єкти — короткий напис, нерухоме фото, звук сирени/дзвоника за натисканням, рухоме відео.
- **«З'єднай» (`match`):** вуха↔дзвоник, очі↔веселка, ніс↔запах квітки, шкіра↔дотик до снігу; запитання озвучені; обов'язково чітко відрізнити фізичний світ від цифрових файлів.
- **«Знайди зайве» (`choice`):** серед чотирьох стимулів три статичні зображення й одне коротке рухоме відео — обрати відео.

**Створи сам:** не обов'язково; дозволений простий звуковий/візуальний дослід, але не малювання «будь-чого».

**Перевір себе — 4 нових приклади цифрової інформації:** (1) незнайомий короткий напис «САД» → **текст**; (2) новий звук дзвоника, який дитина відтворює кнопкою ▶ → **звук**; (3) нерухоме фото білки → **зображення**; (4) короткий фрагмент, де рухається велосипед → **відео**. Для кожного — чотири великі варіанти «Текст / Зображення / Звук / Відео» з озвученням. **Органи чуття обов'язково тренувати** у вкладці «З'єднай»; за потреби методист може додати **окрему необов'язкову** мініперевірку на «очі / вуха / ніс / дотик». Статус ключового результату цього уроку визначає розрізнення чотирьох форм інформації, не лише знання органів чуття.

**Уникай:** статичний малюнок людини, яка біжить, — це ще не відео. Звуковий файл має реально відтворювати звук після натискання.

### Урок 05. Я знаходжу спільне

- **Запитання:** «Що між ними спільного?»
- **Результат:** помічає ознаки об'єктів (колір, форма, призначення, розмір), групує за **заданою ознакою** і може пояснити вибір малюнком або коротким словом.

**Відео:** (1) Юна показує яблуко й грушу: обидва фрукти. (2) Круглі й квадратні іграшки розходяться по двох кошиках. (3) Машини різних кольорів групуються **за кольором**, потім **за видом транспорту**. (4) Один об'єкт може належати до різних груп залежно від правила. (5) Картка «Обери ознаку».

**Запам'ятай:**
1. «Об’єкти мають ознаки.»
2. «Знайди, що в них спільне.»
3. «Спочатку подивись на правило.»

**Спробуй:** розкласти червоне яблуко й червону кульку в групу «червоні», а сині речі — в групу «сині» (дві групи, `sort`).

**Потренуйся:**
- **«Розклади» (`sort`):** за формою: кола / квадрати; за призначенням: транспорт / посуд; за кольором: червоні / сині.
- **«Зайве» (`choice`):** три предмети для малювання й одна ложка, запитання «Що не для малювання?» — 4 зображення, не текстова класифікація.
- **«Зміни правило» (`sort`):** одні й ті самі 6 предметів спершу за кольором, потім за формою. Особливе завдання на гнучкість мислення.

**Створи сам:** за бажанням «Збери колекцію»: дитина сама обирає ознаку зі списку великих значків і кладе 3 картки; автоматично оцінювати лише задану ознаку.

**Перевір себе:** (1) групування іграшок за формою; (2) групування транспорту за рухом по землі/воді; (3) вибір зайвого із 4 предметів, де правило явно сказано; (4) повторне групування тих самих 4 об'єктів за **новою ознакою**. Не використовувати приклади з тренування.

### Урок 06. Я розумію моделі та схеми

- **Запитання:** «Як малюнок допомагає знайти шлях?»
- **Результат:** розуміє, що модель показує важливі частини/ознаки об'єкта; співвідносить об'єкт із простою моделлю, читає умовні знаки на плані.
- **Ключова відмінність від уроку 05:** тут не сортування як самоціль, а **представлення реальності моделлю**.

**Відео:** (1) Юджі бачить справжній глобус і Землю на зображенні — глобус є моделлю. (2) Вид згори на кімнату стає простим планом: двері, стіл, шафа. (3) На плані школи з’являється умовний знак сходів. (4) Юна йде по плану до бібліотеки. (5) Порівняння: план показує не всі деталі, тільки потрібні.

**Запам'ятай:**
1. «Модель показує головне.»
2. «План допомагає знайти місце.»
3. «Знаки на плані мають значення.»

**Спробуй:** знайти відповідність «фото кімнати» ↔ «план тієї самої кімнати» серед двох чітких карток (`modelMatch`, `match`).

**Потренуйся:**
- **«З'єднай» (`modelMatch`):** справжнє дерево ↔ спрощений малюнок дерева; Земля ↔ глобус; кімната ↔ план; автобус ↔ схема автобуса. Не давати неоднозначних моделей.
- **«Знайди» (`tap` на плані):** план з великими зонами «двері / стіл / вікно / шафа»; інструкція «Знайди двері» з аудіо.
- **«Покажи шлях» (`sequence` / `grid-runner`):** за схемою 3×3 провести Юджі від входу до книжки, 2–4 кроки без дрібної моторики.

**Створи сам:** **намалюй план парку** із 3 готових об'єктів (вхід, дерево, лавка), розмісти за зразком. Це конструювання схеми, не вільне малювання; клавіатурна й tap→tap альтернатива.

**Перевір себе:** (1) вибрати модель об’єкта із 4 ілюстрацій; (2) на **новому** плані знайти позначену кімнату; (3) зіставити умовний знак із предметом; (4) пройти простий маршрут за незнайомою схемою. Зафіксувати окремо результат читання моделі, а не лише натискань.

### Урок 07. Я розгадую коди

- **Запитання:** «Що ховається за знаками?»
- **Результат:** розуміє, що домовлені знаки можуть передавати інформацію, застосовує просте правило кодування/декодування, створює візерунок за кодом.
- **Не вчити:** двійкову арифметику, криптографічні алгоритми, ASCII, складні шифри.

**Відео:** (1) Юна й Юджі домовляються: ⭐ означає «іди вперед», ● — «зупинись». (2) Юджі читає два символи та виконує дії. (3) Таблиця: число 1 — синя клітинка, число 2 — жовта. (4) З'являється піксельний малюнок за короткою послідовністю чисел. (5) Те саме повідомлення можна показати словом, знаком або малюнком — за відомим правилом.

**Запам'ятай:**
1. «Знак може щось означати.»
2. «Правило допомагає читати код.»
3. «Один код — одна домовленість.»

**Спробуй:** показати легенду «1 = синій, 2 = жовтий»; натиснути клітинку зі зразком `1`, вибрати синій (`pixelCode`).

**Потренуйся:**
- **«Розфарбуй» (`pixelCode`):** 4×4 сітка, дві барви, код над кожною клітинкою; дитина обирає колір із великих кнопок, потім клітинку. Приклад — простий хрест/вікно, не складний малюнок.
- **«Розшифруй» (`match`):** ⭐/●/▲ відповідають «рухайся»/«стій»/«поверни» за чіткою легендою; зіставити символ та дію.
- **«Знайди код» (`choice`, 4 варіанти):** за готовим візерунком вибрати відповідний ряд із 4 коротких кольорових кодів; помилки демонструють різницю.

**Створи сам:** «Створи свій код»: 3×3 піксельна сітка з двох кольорів → сервіс **показує автоматично згенерований код** → дитина може повторно відтворити його в іншій сітці. Зберігається локально; без оцінювання художньої якості.

**Перевір себе:** (1) нова легенда A=коло, B=квадрат: вибрати правильний символ за командою; (2) розфарбувати **новий** ряд із 4 клітинок за кодом; (3) зіставити 3 нові позначки з діями; (4) вибрати з 4 коротких закодованих рядів той, що відповідає заданому візерунку. Першочерговий результат — **застосування нового правила**, а не запам'ятовування одного шаблону.

**Доступність:** у клітинках потрібні й символи/номери, не лише колір; альтернативний режим вибору клітинок стрілками, керування палітрою клавіатурою.

### Урок 08. Я перевіряю інформацію

- **Запитання:** «Чи всьому можна вірити?»
- **Результат:** розрізняє очевидний факт, думку й твердження, для якого немає достатніх доказів; знає простий наступний крок — запитати, перевірити в надійному джерелі з дорослим.
- **Важливо:** не створювати фальшивий висновок «усе із красивої картинки правдиве» або «все, що сказав незнайомець, точно неправда». Ключове поняття — **достатність підстав для впевненості**.

**Відео:** (1) Юджі бачить фото яблука й твердження «На фото яблуко» — можна перевірити на зображенні. (2) Юна каже «Яблука — найсмачніші» — це її думка. (3) Невідоме повідомлення: «Завтра всі уроки скасовано» — із самого повідомлення ми цього не знаємо. (4) Юна звертається до офіційного повідомлення школи / вчителя, який може підтвердити інформацію. (5) «Не впевнений? Перевір перед тим, як повторювати».

**Запам'ятай:**
1. «Факт можна перевірити.»
2. «Думка — це те, що хтось вважає.»
3. «Не знаєш напевно? Перевір.»

**Спробуй:** наочно показати яблуко; обрати, яке з чотирьох висловлювань підтверджує картинка (наприклад «Це яблуко» серед не пов'язаних зображень/коротких слів), озвучити (`sourceCheck`).

**Потренуйся:**
- **«Факт чи думка?» (`sort`):** чіткі приклади з картинками: «На фото два коти» (якщо їх справді два), «Коти наймиліші» (думка); «Сонце намальоване жовтим» (факт **про малюнок**), «Жовтий — найкращий колір» (думка).
- **«Треба перевірити» (`safetyScenario` / `sourceCheck`):** вигадана новина про зміну заняття, відсутня інформація про джерело → обрати безпечну дію «Звірити з повідомленням школи/вчителем» серед 4 варіантів.
- **«Знайди доказ» (`match`):** питання «Скільки квіток на фото?» ↔ картинка з квітками; «Коли починається гурток?» ↔ оголошення з часом (великі цифри й озвучення); «Який колір любить Юна?» ↔ це особиста думка/вподобання, запитати саму Юну.

**Створи сам:** за бажанням «Підпиши фото» вибором одного **точного** короткого підпису; відкритий редактор не потрібний.

**Перевір себе:**
1. На новому зображенні 3 кульки. Твердження «Тут три кульки» — **факт, який підтверджує зображення** (4 варіанти дії/висновку з піктограмами).
2. «Блакитний колір найгарніший» — **думка** (4 короткі варіанти/картки: факт, думка, команда, назва).
3. В анонімному повідомленні написано «Завтра уроків немає», без підтвердження — **перевірити у школі/дорослого**, а не позначити як «брехня».
4. Порівняти два **навчальні макети** повідомлень: одне має чітку дату, назву школи та підтвердження, друге — анонімний скриншот. Обрати **що варто перевірити першим** і чому в дуже короткій формі. **Не стверджувати, що назва школи на скриншоті автоматично гарантує правду** — імітації можливі.

**Доступність/етика:** текст на картках озвучений; навички факт/думка оцінюються окремо від швидкості читання. Не використовувати реальні тривожні воєнні повідомлення, дезінформацію або лякаючі приклади для 7–10 років.

## РОЗДІЛ C. СТВОРЮЮ ТА ЗБЕРІГАЮ

### Урок 09. Я створюю текст і малюнок

- **Запитання:** «Як зробити власну листівку?»
- **Результат:** створює маленький цифровий продукт із зображення та короткого підпису, використовує базові інструменти й за потреби виправляє помилку.
- **Механіка:** один справжній редактор (`miniEditor`), а не тест, який удає редактор.

**Відео:** (1) Порожня листівка. (2) Юна вибирає фон. (3) Додає наліпку або малює просту фігуру. (4) Вводить короткий текст «ВІТАЮ!» або вибирає підпис із готових карток. (5) Передивляється, виправляє й зберігає (зв'язок з наступним уроком).

**Запам'ятай:**
1. «Обери фон або колір.»
2. «Додай малюнок.»
3. «Напиши короткий підпис.»

**Спробуй:** додати в порожню листівку одну велику наліпку (серце, зірка, квітка) (`miniEditor`).

**Потренуйся:**
- **«Намалюй» (`draw` / `miniEditor`):** намалювати сонце з готових фігур або простим пензликом; доступне додавання фігури тапом.
- **«Додай слова» (`miniEditor` + `virtualKeyboard`):** написати «ВІТАЮ» або вибрати короткий підпис із доступних готових варіантів. Щоб зарахувати **реальний набір** тексту, перевіряти його в уроці 03, не тут.
- **«Виправ» (`miniEditor`):** прибрати зайву наліпку, змінити фон, виправити короткий підпис або відмінити останню дію.

**Створи сам — ОБОВ'ЯЗКОВО:** власна листівка: фон + принаймні один елемент зображення + підпис (набір або вибір доступного тексту). Збережений результат потім доступний у вправі уроку 10. Усе локально, без передачі фото дитини на сервер.

**Перевір себе:** виконати **одне нове практичне завдання із чотирма об'єктивними умовами**: (1) змінити фон; (2) додати зірку; (3) додати короткий підпис; (4) прибрати зайвий елемент. Критерій — операції виконані. **Не перевіряти** «красу» листівки і не вимагати друку великого тексту на смартфоні.

### Урок 10. Я зберігаю свою роботу

- **Запитання:** «Де знайти мій малюнок?»
- **Результат:** розуміє послідовність **створити → зберегти → знайти → відкрити**, відрізняє автозбереження та явну кнопку «Зберегти» на рівні симуляції, знає про галерею/мої роботи/файли.

**Відео:** (1) Юджі малює. (2) Натискає «Зберегти»; листівка з'являється у «Моїх роботах». (3) Юна показує застосунок, де зміни зберігаються автоматично. (4) Юджі відкриває свою листівку ще раз. (5) На комп'ютері та планшеті вигляд сховища може бути різним, але роботу можна знайти.

**Запам'ятай:**
1. «Роботу можна зберегти.»
2. «Шукай у «Моїх роботах».»
3. «Відкрий — і продовжуй.»

**Спробуй:** натиснути «Зберегти» у тренувальній симуляції; побачити мініатюру (`saveFind`).

**Потренуйся:**
- **«Збережи» (`saveFind`):** завершити просту картинку з уроку 09 й явно зберегти.
- **«Знайди» (`saveFind`):** серед трьох зображень у «Моїх роботах» знайти потрібне за мініатюрою, відкрити.
- **«Де шукати?» (`match`):** фото↔Галерея, малюнок↔Мої роботи, документ↔Файли/Документи; **пояснити, що в різних пристроях це може бути по-різному**.

**Створи сам:** використати листівку з уроку 09, не дублювати редактор. Якщо її немає, надати коротку локальну демороботу.

**Перевір себе:** (1) створити демомалюнок; (2) зберегти; (3) відкрити «Мої роботи»; (4) знайти та відкрити саме створений малюнок. Варіант Б для автозбереження — відкрити збережену автоматично нотатку за зрозумілим індикатором. Ніколи не оцінювати за конкретним шляхом Windows чи iPadOS.

**Технічний нюанс:** навчальна робота має окремий стабільний ключ збереження і не повинна зникати від простого переключення вкладок. При відмові `localStorage` попередити **дорослого** про тимчасовий прогрес, не лякати дитину.

## РОЗДІЛ D. ІНТЕРНЕТ І БЕЗПЕКА

**Запам'ятай:**
1. «Сайт має сторінки.»
2. «Посилання відкриває сторінку.»

**Спробуй:** тапнути велику картку «Тварини» у `browserSim`, дочекатися переходу.

**Потренуйся:**

**Безпека:** ніяких реальних зовнішніх посилань в інтерактивному сценарії для дітей.

### Урок 12. Я знаходжу потрібне

- **Запитання:** «Які слова допоможуть знайти відповідь?»
- **Результат:** із кількох варіантів обирає конкретний пошуковий запит і співвідносить результат із початковим запитанням.

**Відео:** (1) Юна хоче дізнатися, чим харчується їжак. (2) Дуже загальне слово «тварини» показує багато зайвого. (3) Запит «чим харчується їжак» точніший. (4) На екрані різні результати, Юна обирає той, що відповідає питанню. (5) Не всі результати автоматично правдиві — за потреби перевір.

**Запам'ятай:**
1. «Подумай, що шукаєш.»
2. «Назви головні слова.»
3. «Перевір, чи це відповідь.»

**Спробуй:** для питання «Де живе жирафа?» обрати «де живе жирафа» з чотирьох варіантів (`searchSim`), усі варіанти озвучуються.

**Потренуйся:**
- **«Обери запит» (`searchSim`, 4 відповіді):** питання «Як виглядає сова?» — серед «птахи / сова гра / як виглядає сова / великі тварини».
- **«Знайди відповідь» (`choice`):** серед чотирьох макетів результатів вибрати зображення й короткий опис, що відповідає поставленому питанню.
- **«Скажи точніше» (`searchSim`):** з загального «погода» вибрати варіант, у якому з'являється місце або потрібний показник, **без запиту реальної геолокації**.

**Створи сам:** не потрібно.

**Перевір себе:** (1) «Чим харчується білка?» → точний запит; (2) «Який вигляд має автобус?» → запит із назвою; (3) з чотирьох симульованих результатів знайти сторінку про названу тварину; (4) вибрати, як звузити занадто загальний запит. Усі сценарії нові відносно тренування.

**Пастка:** вік дитини не дозволяє робити обов'язковим самостійний відкритий вебпошук; у курсі лише симуляція. Перевірку достовірності відпрацьовує урок 08.

### Урок 13. Я захищаю особисте

- **Запитання:** «Що не варто надсилати незнайомцям?»
- **Результат:** розрізняє особисте та нейтральне, враховує контекст, розуміє, що цифрові повідомлення й фото можуть поширюватися, поважає приватність інших.

**Відео:** (1) Юна ділиться своєю улюбленою твариною — це зазвичай не приватна інформація. (2) У грі незнайомець просить домашню адресу — не надсилати. (3) На фото випадково видно адресу/номер телефону — спочатку подумати й прибрати зайве. (4) Друг на фото: перед публікацією слід запитати дозволу. (5) Надіслане повідомлення можуть переслати іншим, тому варто подумати до відправлення.

**Запам'ятай:**
1. «Не надсилай адресу й номер телефону незнайомцям.»
2. «Перед фото — подумай і запитай дозволу.»
3. «Повідомлення можуть побачити інші.»

**Спробуй:** побачити чат у грі: незнайомець просить адресу → обрати безпечну дію серед 4: «Не відповідати й сказати дорослому» тощо (`safetyScenarios`).

**Потренуйся:**
- **«Особисте чи ні?» (`sort`):** домашня адреса/номер телефону/пароль та улюблена тварина/колір; **обов'язково контекст** «незнайомцю в грі».
- **«Знайди на фото» (`tap`):** навчальний макет фотографії з видимим будинковим номером, бейджем школи й номером телефону; натиснути деталі, які варто приховати перед надсиланням.
- **«Що зробиш?» (`safetyScenarios`):** фото друга без його дозволу; прохання показати своє місце розташування; повідомлення з приватними даними.

**Створи сам:** **зроби фото без зайвого** — із готової навчальної картинки прибрати/закрити наліпками 2 особисті деталі; без завантаження справжніх фотографій дітей.

**Перевір себе:** (1) чат просить номер телефону — безпечна дія; (2) на навчальному фото видно домашню адресу — знайти її; (3) чи можна викласти фото друга без дозволу — вибрати «спочатку запитати»; (4) повідомлення з улюбленим кольором без персональних деталей — розрізнити від особистих даних. Не позначати все про дитину автоматично «забороненим»: потрібен контекст.

### Урок 14. Я бережу свої паролі

- **Запитання:** «Навіщо потрібен пароль?»
- **Результат:** розуміє, що пароль захищає доступ, не надсилає його іншим дітям і незнайомцям, упізнає очевидно слабкі приклади, знає, до якого відповідального дорослого звернутися по допомогу.

**Відео:** (1) У Юджі є ігрова шафка/скринька з замком — образ пароля як захисту. (2) Простий пароль «1234» легко вгадати. (3) Довша вигадана фраза зі складними для вгадування словами надійніша; пояснювати без правил, які дитина змушена запам'ятовувати механічно. (4) Незнайомець просить пароль у чаті — Юджі не надсилає. (5) Юна радить звернутися до батьків/опікуна, якщо пароль забуто або хтось його дізнався.

**Запам'ятай:**
1. «Пароль захищає вхід.»
2. «Не надсилай пароль друзям чи незнайомцям.»
3. «Потрібна допомога? Скажи дорослому.»

**Спробуй:** із чотирьох **навчальних вигаданих** прикладів вибрати очевидно найважчий для вгадування (`passwordGame`); поруч коротке пояснення.

**Потренуйся:**
- **«Міцніший пароль» (`passwordGame`):** порівняти очевидні «123456», «ім'я+рік» і довшу фразу; використовувати приклади, які явно позначені як **не для реального входу**.
- **«Кому сказати?» (`safetyScenarios`):** друг просить пароль; незнайомець обіцяє бонус у грі; дорослий допомагає повернути доступ до власного дитячого акаунта. Показати правильну поведінку, не «ніколи ні з ким».
- **«Що робити?» (`sequence`):** якщо пароль став відомий незнайомому — припинити розмову → сказати дорослому → разом захистити акаунт; не вимагати від 7-річної дитини самостійної зміни всіх налаштувань.

**Створи сам:** немає. **Ніколи не створювати поле для справжнього пароля**, не збирати й не зберігати чутливі значення.

**Перевір себе:** (1) серед чотирьох вигаданих паролів вибрати важчий для вгадування; (2) незнайомець просить пароль → відмовитись і сказати дорослому; (3) хтось дізнався пароль → повідомити дорослого; (4) вибрати правильне твердження «Пароль захищає вхід» серед чотирьох коротких карток.

### Урок 15. Я знаю, що робити онлайн

- **Запитання:** «Що робити, якщо онлайн щось не так?»
- **Результат:** застосовує зрозуміле правило дій у разі загрозливого або дивного повідомлення в чаті, грі, браузері. Знає, що відповідальний дорослий допоможе.

**Відео:** (1) Юджі грає; незнайомець просить особисте фото. (2) Юджі **зупиняється**, нічого не надсилає. (3) Закриває чат/перестає відповідати; якщо потрібно, блокує незнайомця разом із дорослим. (4) Розповідає дорослому, якому довіряє. (5) Юна нагадує: «Якщо неприємно або страшно — не залишайся із цим сам».

**Запам'ятай:**
1. «СТОП — не відповідай.»
2. «ЗАКРИЙ — припини розмову.»
3. «СКАЖИ дорослому, якому довіряєш.»

**Спробуй:** розкласти три великі картки **СТОП → ЗАКРИЙ → СКАЖИ** (`sequence`), підказка-анімація допустима.

**Потренуйся:**
- **«Що робити?» (`safetyScenarios`):** незнайомий аватар просить адресу, фото, зустріч або секрет. Варіанти дій великі, озвучені.
- **«Впізнай сигнал» (`tap`):** в імітації чату натиснути фразу «Нікому не кажи», «Надішли фото», «Я знаю, де ти живеш»; без нав'язливо страшних зображень.
- **«Постав по порядку» (`sequence`):** відтворити безпечний порядок дій на **новій** ситуації з дивним посиланням або образливим повідомленням.

**Створи сам:** необов'язково. Можлива коротка вправа «Кого покличеш?» із заздалегідь заданими персонажами-дорослими (батьки, вчитель, опікун), без збору їхніх імен.

**Перевір себе:** 4 нові ситуації: (1) чат просить секрет; (2) незнайомець пропонує зустріч; (3) образливе повідомлення; (4) незрозуміле посилання з обіцянкою подарунка. Для кожної — чотири варіанти дій; правильний тип: не продовжувати ризиковану взаємодію, розповісти довіреному дорослому. Не карати дитину за те, що ситуація виникла.

**Педагогічна примітка:** коротка тріада — мнемонічне правило, не універсальний юридичний протокол. Наприклад, при кібербулінгу дорослому може знадобитися зберегти докази; дитині достатньо припинити небажаний контакт і звернутися по допомогу.

### Урок 16. Я даю команди

- **Запитання:** «Як допомогти Робі дійти до зірки?»
- **Результат:** пов'язує точну команду з дією, складає просту послідовність команд, обирає маршрут на невеликій сітці.
- **Зберегти:** спільного робота **Робі**, `robotUI`, `commandLab` та `routeRunner`; за потреби додати Юну/Юджі лише як ведучих, не замінювати героя без потреби.

**Відео:** (1) Юджі знайомить із Робі на полі 3×3. (2) «Вгору» — Робі рухається на одну клітинку; показати межу поля. (3) Кілька команд виконуються **по черзі**. (4) На полі з'являється перешкода; потрібно її обійти. (5) Робі досягає зірки; різні безпечні маршрути можуть бути правильними.

**Запам'ятай:**
1. «Одна команда — один крок.»
2. «Порядок команд важливий.»
3. «Запусти й подивись, куди йде Робі.»

**Спробуй:** один натиск на стрілку для переміщення Робі до сусідньої клітинки (`commandLab`).

**Потренуйся:**
- **«Команда» (`commandLab`):** обрати одну правильну стрілку ↑↓←→ на полі 3×3.
- **«Склади маршрут» (`routeRunner`):** 2–4 команди на полі 4×4 до зірки, без перешкод.
- **«Обійди» (`routeRunner`):** новий маршрут навколо однієї перешкоди; приймати **будь-який** правильний шлях, який досягає мети без зіткнень.

**Створи сам:** намалювати або викласти короткий маршрут для Робі на 4×4, але це не окремий обов'язковий графічний редактор.

**Перевір себе:** (1) дати **одну** правильну команду в новому стартовому положенні; (2) скласти два кроки; (3) скласти маршрут із трьох кроків; (4) побудувати маршрут з однією перешкодою. Для статусу `Вмію` важливий **працюючий алгоритм**, а не співпадіння текстового масиву з єдиною заготовкою.

**Обмеження:** не вводити цикли чи умовні оператори до уроку 18; достатньо чотирьох напрямків і запуску.

### Урок 17. Я виправляю помилки

- **Запитання:** «Чому Робі пішов не туди?»
- **Результат:** бачить невдалий результат, знаходить неправильний крок, змінює його та перевіряє роботу знову.

**Відео:** (1) Робі отримує маршрут до зірки. (2) Після запуску доходить до дерева, а не зірки. (3) Юна показує список команд, виділяє підозрілий крок. (4) Команду змінено; алгоритм запускається з початку. (5) Робі доходить до зірки; помилки допомагають навчатися.

**Запам'ятай:**
1. «Спочатку запусти.»
2. «Знайди неправильний крок.»
3. «Виправ і перевір.»

**Спробуй:** показати вже запущену програму з одним явно помилковим кроком, дати замінити стрілку (`debugRunner`).

**Потренуйся:**
- **«Знайди» (`debugRunner`):** маршрут 3×3 з однією помилкою, підсвічується результат, **але не правильний крок**.
- **«Виправ» (`debugRunner`):** поле 4×4 з одним зайвим поворотом; обрати рядок команди → змінити → запуск.
- **«Перевір» (`debugRunner`):** два різні навчальні маршрути, один вже робочий, один ні; вирішити, чи потрібно щось міняти, не «виправляти» правильне.

**Створи сам:** «Підготуй задачу для Юджі» — агент опціонально може дозволити змінити одну команду в готовій програмі, щоб Юджі її виправив. Не обов'язкове для MVP.

**Перевір себе:** 4 нові алгоритми зі зрозумілою помилкою/перевіркою: (1) замінити 1-шу команду; (2) замінити середню; (3) виявити, що маршрут коректний і не потребує виправлення; (4) виправити команду, яка веде до перешкоди. Для пунктів 1,2,4 обов'язкова послідовність «запуск → зміна → повторний запуск». Система має дійсно симулювати команди, а не просто порівнювати одну «правильну» строку.

### Урок 18. Я повторюю команди

- **Запитання:** «Як записати коротше?»
- **Результат:** помічає однакові послідовні команди, створює блок «Повтори N разів» та перевіряє, що робот виконує стільки ж дій.

**Відео:** (1) Робі має виконати →→→→. (2) Юджі показує чотири однакові стрілки; це довго. (3) Юна замінює їх блоком «Повтори 4 рази →». (4) Під час запуску видно **чотири** кроки — не один стрибок. (5) Два записи дають однаковий результат.

**Запам'ятай:**
1. «Однакові дії можна повторити.»
2. ««Повтори 4 рази» — це чотири дії.»
3. «Коротший запис працює так само.»

**Спробуй:** побачити ↑↑↑, вибрати блок `Повтори 3 рази ↑` (`repeatRunner`).

**Потренуйся:**
- **«Знайди повтор» (`choice`, 4 варіанти):** чотири короткі ряди зі стрілок, лише один має задану кількість однакових команд.
- **«Скороти» (`repeatRunner`):** ↓↓↓↓ → блок «4 × ↓»; потім ←←← → «3 × ←».
- **«Перевір Робі» (`repeatRunner` + `robotUI`):** запустити розгорнутий і скорочений записи на нових полях, порівняти кінцеву позицію й кількість кроків.

**Створи сам:** необов'язково «Намалюй сходинки повтором» за шаблоном із повторюваних кроків; без вкладених циклів.

**Перевір себе:** (1) скоротити чотири ↑; (2) вибрати кількість повторів для п’яти →; (3) знайти з чотирьох записів той, що еквівалентний трьом ↓; (4) запустити простий повтор на полі без перешкод й підтвердити правильну кількість кроків. Не вимагати вкладених циклів, складних блоків, умов та синтаксису мов програмування.

**Фінал курсу:** Юна й Юджі можуть привітати: **«У тебе вийшло!»**. Не показувати на дитячому екрані «18/18 компетентностей державного стандарту».

- `VideoPanel` з постером, відтворенням, субтитрами, запасним текстом;
- `RememberCard` — картинка, 1 фраза, 🔊;
- `PracticeTabs` — семантичні вкладки та одна робоча область;
- `ActivityShell` — інструкція, повторне відтворення, підказка, скидання;
- `CreativePanel` — **лише для вибраних уроків**;
- `AssessmentPanel` — запуск, 4 пункти, підсумок;
- `ProgressBadge` — «Нове», «Тренуюся», «Майже», «Вмію»;
- `MascotHint` — необов'язкова коротка репліка Юни/Юджі.

Усі застосовують існуючі змінні CSS. Палітри категорій можуть мати свої пастельні підкладки, але **не** незалежні шрифти, радіуси та нескінченні градієнти.

## 8.3. Макет на різних екранах

- **320–599 px:** один стовпчик; великі кнопки; відео 16:9 на всю доступну ширину; вкладки горизонтально прокручуються або розміщуються у 2 ряди; активні зони вправ не менше **48×48 px**, бажано 56–60 px.
- **600–1023 px:** 2–3 картки пояснень у ряд за наявності місця; робоча зона інтерактиву достатньо велика.
- **1024 px+**: контент сторінки має читабельну максимальну ширину; для вправ дозволено ширший контейнер, але не надмірно довгі рядки тексту.
- **Zoom 200–400%:** відсутність накладання; відсутність втрати змісту або кнопок; картки переходять в один стовпчик.
- Sticky-елементи не перекривають фокусовані поля або кнопку «Далі». Якщо нижня навігація лишається, врахувати safe-area та її висоту.

# 9. Доступність, слабке читання й підтримка моторики

## 9.1. Текст, зображення, звук

- Кнопка: орієнтир 1–3 слова. Інструкція: 1–5 слів. Картка: одне коротке речення, якщо потрібно.
- **Не видаляти текст повністю**: текст + наочність + необов’язкове озвучення допомагають упізнавати слова.
- Не покладатися лише на озвучення: користувач може вимкнути звук, браузер може не мати українського голосу або бути офлайн.
- При використанні синтезу мовлення мати запасний варіант: видимий короткий текст, а для ключового відео — субтитри і текстовий виклад. Не обіцяти стабільний український TTS на кожному пристрої.
- Не використати **філворд** як обов'язкове завдання на досягнення цифрової навички: він переважно перевіряє читання.
- Не використовувати системні emoji як основні навчальні ілюстрації. Картки мають отримувати локальні SVG/PNG із єдиної стилістики.

## 9.2. Клавіатура й вказівник

- Усі обов'язкові вправи проходяться мишею, touch або клавіатурою. Для drag-and-drop обов'язковий **tap→tap/click→click** та/або доступне кнопкове керування.
- Обрані та фокусовані елементи мають чіткий контур і стан, а не тільки колір.
- Після зміни вкладки **фокус переходить на її заголовок/робочу зону** за передбачуваною схемою; використовувати семантичні `button`, `tablist`, `tab`, `tabpanel`, керування стрілками відповідно до ARIA tabs pattern.
- `aria-live` для короткого результату; не зачитувати весь екран щоразу при кліку.
- Поле маршруту має доступний текстовий опис «Робі: рядок 2, стовпець 1; ціль ...», а команди є звичайними кнопками.
- `prefers-reduced-motion: reduce` спрощує переміщення й візуальні ефекти без втрати пояснювальної інформації.
- `forced-colors` і підвищена контрастність мають зберігати межі карток, видимість тексту та фокус.

## 9.3. Тестування з дітьми

Перед масовим наповненням усіх уроків провести коротку перевірку хоча б **одного уроку з кожного типу навичок**: на дитині, що читає впевнено, і дитині, що читає невпевнено, **за належної згоди батьків/школи**.

Відзначати лише анонімні спостереження: що дитина зрозуміла без пояснення; де шукала кнопку; коли помилково натискала; чи знайшла 🔊; чи виконала дію самостійно. **Не збирати ПІБ, дату народження, голосові записи або відеозаписи дитини для цього тесту без окремої правової та етичної підстави.**

# 10. Контентна модель для агента

Потрібно відокремити педагогічний контент від відображення й механіки. Концептуальний приклад (це **схема**, не обов'язково готовий код для копіювання без змін):

```js
{
  skillKey: 'models-schemes',
  order: 6,
  category: 'information',
  title: 'Я розумію моделі та схеми',
  question: 'Як малюнок допомагає знайти шлях?',
  media: {
    video: 'assets/video/06-models.webm',
    poster: 'assets/images/lessons/06-poster.webp',
    captions: 'assets/video/06-models.uk.vtt',
    fallbackStory: [/* 5 коротких кадрів */],
    ready: false // true ЛИШЕ після перевірки реального файлу
  },
  remember: [
    { text: 'Модель показує головне.', image: '...', audio: '...' },
    { text: 'План допомагає знайти місце.', image: '...', audio: '...' }
  ],
  demo: { type: 'modelMatch', items: [/* ... */] },
  practice: [
    { id: 'pairs', label: 'З’єднай', type: 'modelMatch', items: [/* ... */] },
    { id: 'find', label: 'Знайди', type: 'tap', items: [/* ... */] },
    { id: 'route', label: 'Покажи шлях', type: 'grid-runner', items: [/* ... */] }
  ],
  create: { enabled: true, type: 'plan-builder' },
  assessment: {
    version: 1,
    tasks: [/* 4 нові приклади, відмінні від practice */]
  }
}
```

**Вимоги до даних:**

- У `choice` кожне запитання має **4 опції** з одним коректним `answerId`. Система не має покладатися на позицію «друга правильна».
- Дані для контролю лежать окремо від тренувальних і мають `assessmentVersion`, щоб зміни змісту не приписували старе досягнення новій перевірці.
- Система може зберігати фактичні обрані відповіді **тільки локально, мінімально необхідно й без персональних даних**; для MVP достатньо статусу, версії оцінювання й технічного коду навички.
- Якщо контент містить аудіо, передбачити український текстовий еквівалент. Файли та їхні URI тільки локальні або явно дозволені.
- Не показувати файл відео з помилкою 404; якщо матеріалу немає, замінити на доступне поетапне пояснення та позначити незавершене виробництво **у документації дорослим**.

# 14. Вирішальні застереження

1. **Не збільшувати курс понад 18 уроків у MVP.** Якщо з'явиться нова тема, спершу перевірити, чи це наскрізна вправа або розширений рівень.

3. **Не жертвувати базовими навичками заради mobile-first.** Клавіатура, збереження, створення продукту та маршрути мають залишитися, але працювати на різних пристроях.
4. **Не робити однакові три вправи в усіх уроках.** Механіка обирається за конкретним результатом.
5. **Не примушувати дитину малювати в кожному уроці.** Творча дія повинна мати сенс.
6. **Не називати всі повідомлення в Інтернеті «правдою» або «брехнею».** Навчити дитину визнавати невизначеність і перевіряти.
7. **Не ставити «Вмію» за старим числовим ID після зміни змісту.** Спершу перевірити відповідність новому результату.
8. **Не приховувати статусу медіа.** Відсутнє відео ≠ готовий урок із відео.
