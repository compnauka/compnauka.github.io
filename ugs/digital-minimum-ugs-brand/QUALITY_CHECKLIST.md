# Quality checklist — обов’язково перед merge

Цей чекліст призначений для ШІ-агентів і людей, які створюють нові екрани або вправи.

## 1. Контент
- [ ] На екрані є одна головна навчальна дія.
- [ ] Інструкція коротка і починається з дієслова.
- [ ] Довге пояснення не потрібне для старту вправи.
- [ ] Аудіо дублює, але не замінює критично важливий зміст.
- [ ] Навичка, яку перевіряє механіка, відповідає заявленій освітній цілі.

## 2. Responsive
Перевірити щонайменше:
- [ ] 320×800;
- [ ] 390×844;
- [ ] 768×1024;
- [ ] 1024×768;
- [ ] 1440×900.

На кожній ширині:
- [ ] немає горизонтального скролу сторінки;
- [ ] кнопки не накладаються;
- [ ] fixed/sticky UI не перекриває останній контент;
- [ ] довгі українські заголовки переносяться без обрізання змісту.

## 3. Zoom / reflow
- [ ] 200% browser zoom — сторінка придатна до використання;
- [ ] при сильному збільшенні колонки перебудовуються;
- [ ] функція не втрачається через прихований/обрізаний елемент.

## 4. Keyboard
- [ ] весь функціонал доступний без миші;
- [ ] Tab-порядок логічний;
- [ ] `focus-visible` добре видно;
- [ ] Enter/Space активують кнопки;
- [ ] drag-and-drop має keyboard/tap альтернативу.

## 5. Touch
- [ ] ключові цілі ≥48×48px;
- [ ] між сусідніми дрібними цілями є достатній проміжок;
- [ ] немає дій, що залежать лише від hover;
- [ ] помилковий tap легко виправити.

## 6. Screen reader / semantics
- [ ] один `h1` на сторінці;
- [ ] логічна ієрархія заголовків;
- [ ] `button` використовується для дії, `a` — для переходу;
- [ ] значущі зображення мають `alt`;
- [ ] декоративні SVG приховані через `aria-hidden`;
- [ ] icon-only controls мають accessible name;
- [ ] `aria-live` не спамить повідомленнями;
- [ ] прогрес має `aria-valuetext`.

## 7. Color / motion
- [ ] інформація не передається лише кольором;
- [ ] звичайний текст має достатній контраст;
- [ ] `prefers-reduced-motion` не ламає сценарій;
- [ ] `prefers-contrast: more` зберігає читабельність;
- [ ] немає миготіння/нескінченної декоративної анімації.

## 8. Progress states
- [ ] нова навичка = `new`, а не `training`;
- [ ] після спроби можливі `training`, `almost`, `mastered`;
- [ ] дитина не бачить каральних відсотків/балів;
- [ ] повторне проходження завжди дозволене.

## 9. Storage / privacy
- [ ] немає обов’язкової реєстрації;
- [ ] немає імен/персональних даних дітей;
- [ ] немає third-party analytics/ads;
- [ ] localStorage exception не ламає застосунок;
- [ ] користувачу зрозуміло, що прогрес локальний.

## 10. Low bandwidth / offline
- [ ] немає зовнішніх CDN;
- [ ] немає autoplay відео;
- [ ] відео має poster/fallback;
- [ ] головна не завантажує важкі медіа;
- [ ] core shell працює після кешування service worker;
- [ ] великі аудіо/відео не додаються до precache без окремого рішення.

## 11. Error feedback
- [ ] неправильна відповідь не соромить дитину;
- [ ] помилка не просто блокується;
- [ ] після повторних помилок з’являється м’яка підказка;
- [ ] є можливість спробувати ще раз.

## 12. No-JS / failure resilience
- [ ] головна має зрозумілий `noscript` fallback;
- [ ] базова навігація не стає «порожнім екраном» через одну JS-помилку;
- [ ] сторінка не залежить від API для першого рендера.


## Дитячий текст

- [ ] дитячий бренд — «Цифрові суперсили»;
- [ ] немає «цифрового мінімуму», localStorage, реєстрації, методики оцінювання або архітектури в дитячому UI;
- [ ] заголовок не дублюється у topbar і вмісті;
- [ ] інструкція коротка й починається з дії;
- [ ] пояснення — одне коротке речення, якщо можна;
- [ ] новий термін показаний лише якщо він є навчальною ціллю;
- [ ] безпечні сценарії конкретні й зрозумілі;
- [ ] аудіотекст не перетворюється на приховану довгу лекцію;
- [ ] інформація для дорослих винесена на `adults.html`.
