# Design system v2 — «Цифровий мінімум»

Це **обов'язкова специфікація UI** для всіх ШІ-агентів. Вона доповнює `PRODUCT_SPEC.md` і `AGENT_PROMPT.md`.

## 1. Головний принцип

Інтерфейс має виглядати як сучасний дружній дитячий продукт у стилі референсів: тепле світле тло, великі округлі поверхні, пастельні навчальні картки, темно-синій текст, зелена основна дія, мінімум візуального шуму.

При конфлікті між «ефектністю» і зрозумілістю завжди перемагає зрозумілість.

## 2. Токени

Єдине джерело правди: `css/tokens.css`.

Не додавати випадкові hex, px, тіні, радіуси або кольори у компонентах, якщо відповідний токен уже існує.

### Обов'язкові групи
- canvas/surface;
- text;
- border;
- brand;
- 4 тематичні палітри;
- semantic states;
- focus;
- typography;
- spacing;
- shape;
- shadows;
- layout;
- child-friendly targets;
- motion;
- z-index.

## 3. Графічна система

### Production
Не використовувати platform emoji як основні ілюстрації карток. Вони різняться між Windows/iOS/Android і руйнують цілісність стилю.

Використовувати:
- локальні SVG;
- прості дружні ілюстрації з однаковою товщиною лінії;
- однакову перспективу і пластику;
- пастельний фон і темний контур.

Emoji дозволені лише як другорядний декоративний акцент, якщо він не несе ключового значення.

## 4. Типографіка

- зовнішні web-fonts заборонені в MVP;
- системний rounded-friendly stack у `--font-sans`;
- основний текст ≈16–17px і не менше 16px;
- короткі речення;
- заголовки можуть переноситися;
- не використовувати ALL CAPS для довгих інструкцій;
- не робити світло-сірий дрібний текст.

`--color-text-muted` має бути достатньо контрастним для звичайного тексту.

## 5. Адаптивність

Потрібно підтримувати щонайменше 320 CSS px ширини без горизонтального скролу сторінки.

Орієнтири:
- desktop: >1024px;
- tablet: 768–1024px;
- mobile: ≤768px;
- small mobile: ≤608px;
- very small: ≤384px.

Але використовувати fluid layout, а не будувати чотири різні продукти.

### Reflow
При 200% zoom і до 400% zoom:
- основний контент не повинен накладатися;
- елементи переходять у меншу кількість колонок;
- фіксована нижня навігація не повинна перекривати останню картку;
- горизонтальний скрол дозволений тільки всередині компонента, де він справді потрібен.

## 6. Інтерактивні цілі

Для дітей використовуємо не мінімум WCAG, а комфортніший стандарт:
- основна ціль ≥48×48px;
- бажана ≥52×52px для ключових кнопок;
- проміжок між сусідніми маленькими діями ≥8px.

Не покладатися на hover. Усі функції мають бути доступні tap/click/keyboard.

## 7. Клавіатура й focus

Обов'язково:
- логічний порядок Tab;
- чіткий `:focus-visible`;
- не видаляти outline без повноцінної заміни;
- Enter/Space працюють для кнопок;
- активний елемент не ховається під sticky/fixed UI.

## 8. Drag-and-drop: критичне правило

Жодна навчальна дія не може бути доступною **лише** через drag-and-drop.

Кожна така вправа повинна мати принаймні один еквівалент:
- tap object → tap target;
- keyboard select → target → Enter;
- кнопки «вліво/вправо/до кошика».

Якщо оцінюється не моторика, дрібна точність перетягування не впливає на навчальний результат.

## 9. Аудіо

- звук не стартує автоматично;
- кнопка озвучення має текстову accessible name;
- критично важлива інформація не подається тільки аудіо;
- для відео має бути короткий текстовий/візуальний fallback;
- глобальний перемикач озвучення зберігає лише локальну перевагу.

## 10. Відео й слабкий Інтернет

Через можливі перебої зв'язку:
- відео не autoplay;
- `preload="metadata"` або `preload="none"`;
- poster обов'язковий;
- коротка тривалість 45–120 с;
- поряд має бути варіант «Подивитися картками» або короткий fallback;
- відео не повинно блокувати проходження уроку, якщо не завантажилося;
- медіафайли оптимізувати;
- не вантажити всі відео на головній сторінці.

## 11. Колір і контраст

- колір не є єдиним носієм статусу;
- статус завжди має текст/символ;
- основний текст на поверхні — не менше WCAG AA;
- пастельні кольори — переважно фони;
- не використовувати пастельний текст на пастельному фоні;
- підтримувати `prefers-contrast: more` і `forced-colors`.

## 12. Motion

- не використовувати нескінченні декоративні анімації;
- UI motion 120–260ms;
- жодних миготінь;
- `prefers-reduced-motion: reduce` майже повністю вимикає рух;
- важлива інформація не повинна залежати від анімації.

## 13. Когнітивна доступність

- одна головна дія на екрані;
- сталі дієслова: «Обери», «З'єднай», «Розклади», «Постав по порядку», «Натисни», «Проведи»;
- при першому знайомстві — демонстрація дії;
- без таймерів за замовчуванням;
- без streaks і страху «втратити серію»;
- без негативної оцінки помилки;
- завжди доступні «Спробувати ще» і, де доречно, «Скасувати».

## 14. Стани прогресу

Є чотири UI-стани, але лише три є формувальними оцінками:

1. `new` — **Нове**: дитина ще не виконувала оцінювання;
2. `training` — **Тренуюся**;
3. `almost` — **Майже вмію**;
4. `mastered` — **Вмію**.

Не позначати всі нові навички як «Тренуюся» — це створює хибне уявлення про прогрес.

## 15. Помилки й feedback

Неправильна дія:
- не карає;
- не видає різкий звук;
- не блокує без пояснення;
- дає м'який зворотний зв'язок;
- після 1–2 помилок може показати підказку.

У підсумковому «Я вмію!» підказки мінімізовані, але дитина завжди може повторити.

## 16. Privacy by default

MVP:
- без реєстрації;
- без імен дітей;
- без аналітики третіх сторін;
- без рекламних SDK;
- прогрес — локально на пристрої;
- не збирати персональні дані.

Якщо localStorage недоступний, сервіс має працювати без падіння і пояснити, що прогрес не збережеться.

## 17. Offline / resilience

Статичність — одна з переваг продукту. У стартовому комплекті вже є `sw.js` та `manifest.webmanifest`.

Правила:
- service worker кешує shell, CSS, JS і легкі SVG;
- відео та аудіо не кешуються автоматично;
- урок після першого відкриття може працювати офлайн;
- кеш обов’язково версіонується;
- сервіс не залежить від CDN;
- service worker реєструється лише на HTTPS/localhost, а локальне відкриття файлів залишається працездатним без нього.

## 18. Семантика й screen reader

- semantic HTML;
- правильна ієрархія h1→h2→h3;
- skip-link;
- `aria-live` лише для коротких динамічних повідомлень;
- декоративні SVG — `aria-hidden`;
- meaningful images — `alt`;
- прогрес — `role="progressbar"` з `aria-valuetext`;
- фільтри — кнопки з `aria-pressed`;
- модальні вікна, якщо з'являться, керують focus коректно.

## 19. Головна сторінка

Порядок блоків:
1. короткий hero;
2. «Продовжити / Почати»;
3. прогрес;
4. 4 напрями;
5. 16 карток;
6. коротке privacy/offline пояснення;
7. нижня навігація.

Не дублювати два різні набори фільтрів на одному екрані. Категорійні картки — основний фільтр; кнопка «Показати всі» — скидання.

## 20. Перевірка перед merge

Кожен агент перед завершенням UI-зміни повинен перевірити:
- 320px width;
- 768px;
- 1024px;
- desktop;
- keyboard only;
- 200% zoom;
- reduced motion;
- high contrast/forced colors, якщо можливо;
- без JS — хоча б зрозумілий fallback;
- localStorage blocked — немає падіння;
- жодної зовнішньої залежності;
- немає autoplay;
- немає drag-only interactions.
