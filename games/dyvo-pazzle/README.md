# Диво-Пазл 2.0

Tablet-first PWA-гра для дітей: дитина робить фото або вибирає його з галереї, кадрує пальцями, обирає 4 / 9 / 16 деталей і складає пазл.

## Що змінилося у 2.0

- новий flow: **Фото → кадрування → складність → гра**;
- ручне кадрування: drag одним пальцем + pinch zoom двома;
- фото обробляються локально й не завантажуються на сервер;
- Blob/Object URL замість великих Data URL;
- вихід на головний екран очищає фото та відкликає Object URL;
- camera lifecycle захищений від застарілих async-відповідей;
- drag-and-drop на Pointer Events;
- деталь піднімається над пальцем, є magnetic snap;
- 4 деталі: сильніша підказка, більша зона snap, неправильна деталь повертається назад;
- 9 деталей: стандартна допомога;
- 16 деталей: слабка фонова підказка й точніший snap;
- нейтральні назви складності замість оцінювання дитини;
- контрастні темні написи на жовтих/світлих кнопках;
- CSP, security headers template, allow-list форматів фото та ліміт 20 МБ;
- PWA cache очищає тільки власні кеші `divo-puzzle-*`;
- версія кешу — хеш вмісту, оновлення ассетів доїжджає без ручного втручання;
- оновлення Service Worker не перехоплює вже відкриту стару версію.

## Запуск локально

Не відкривайте `index.html` через `file://`, якщо хочете тестувати PWA або камеру.

```bash
python -m http.server 8080
```

Після цього відкрийте `http://localhost:8080`.

## Публікація

Для камери в production потрібен HTTPS. PWA також слід публікувати по HTTPS.

Серверні заголовки гри живуть у **кореневому** `_headers` сайту, у блоці
`/games/dyvo-pazzle/*`. Цей сайт роздається через Cloudflare Workers Static
Assets (`wrangler.toml` → `[assets] directory = "./"`), а Cloudflare читає
`_headers` тільки з кореня каталогу ассетів — вкладений `_headers` у папці гри
був би просто ще одним публічним файлом. `tools/qa-check.mjs` перевіряє, що
потрібний блок на місці.

На платформі без підтримки `_headers` (наприклад, GitHub Pages напряму) CSP з
`<meta>` в `index.html` продовжує діяти, але `Permissions-Policy`,
`frame-ancestors`, `nosniff` тощо треба додати на рівні CDN або reverse proxy.

Гра розміщена у власному scope `/games/dyvo-pazzle/`, тож її Service Worker не
перетинається з рештою сайту. Не реєструйте його в корені домену.

## Приватність

- фотографії не відправляються на сервер;
- немає сторонніх CDN, бібліотек чи зовнішніх шрифтів;
- єдиний зовнішній скрипт — beacon Cloudflare Web Analytics, який Cloudflare
  сам вставляє в кожну HTML-відповідь сайту: без кукі та фінгерпринтингу, з SRI
  `integrity`, а лічильник шле дані на власний домен сайту (`/cdn-cgi/rum`).
  `connect-src` лишається `'self'`, тож фото все одно нема куди відправити;
- фото живе тільки в пам'яті активної сторінки;
- після виходу на головний екран DOM-посилання на фото очищаються, а Object URL відкликається;
- фото не записується в LocalStorage, IndexedDB чи Cache Storage.

## Оновлення гри

Кеш версіонується автоматично — руками нічого пам'ятати не треба.

```bash
node tools/stamp-cache-version.mjs
```

Скрипт рахує хеш вмісту всіх файлів `APP_SHELL` і записує його в
`CACHE_VERSION` у `service-worker.js`. Це важливо, бо браузер помічає оновлення
PWA лише тоді, коли змінюється сам файл воркера: правка `styles.css` чи
`js/*.js` без цього для нього невидима.

Якщо запустити скрипт забули, гравці все одно отримають оновлення: воркер
працює за стратегією **stale-while-revalidate** — віддає кеш миттєво, а
паралельно тягне свіжу версію у фон, тож наступне завантаження вже нове.
Штамп версії потрібен, щоб оновлення прийшло з першого разу, а старий кеш
коректно вичистився.

`node tools/qa-check.mjs` падає, якщо `CACHE_VERSION` не відповідає вмісту, —
тож забути й не помітити не вийде.

## Автоматична статична перевірка

